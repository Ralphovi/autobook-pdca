Add a test that smuggles the value through a `CorpusRow`. Low severity, because it needs deliberate tampering. But it is the same class of bypass the patch spent two rounds closing on `IndexRow`, here on the production path.

The k+1 rule is the part of `exclude` that #25's leave-one-out numbers rely on, and nothing pins it. ### Advisory — security-review

# Security review (advisory): issue 24, kNN index and abstention gates

**Attacker-reachable inputs this diff touches:** statement memo text (threat model "Where untrusted input enters" item 1, written by the counterparty). It reaches `KnnIndex.query` as the normalised `token`. Index rows come from the user's own booking history, which the threat model trusts, but `IndexRow` provenance is checked anyway. No model output, review file, paperless data, book write or network path is touched.

## Findings

- NEEDS-HUMAN [human] — **Medium** (an abstention gate passes a novel memo as confident: the in-scope part of the "kNN can propose the wrong account" known gap, rated like the Medium "pre-marked `a` when it should be `?`" cases). `src/autobook/pipeline/classifier.py:203-205` (`_Partition.nearest`). The query is vectorised with a `TfidfVectorizer` fitted only on the partition's own tokens, and `transform` silently drops every character n-gram that is not in that vocabulary. So whatever new text a counterparty adds to a known merchant's memo adds **no distance at all**. Only the n-grams the index already knows are compared, and after L2 normalisation (scaling the vector to length 1) a memo made of "known merchant + unseen words" can come out at cosine distance 0 to the known merchant. Synthetic example: a partition whose history is only `BEISPIELMARKT` → `Aufwand:Lebensmittel`. A new statement line normalises to `BEISPIELMARKT QXZV WJKQ HOLDING`. The n-grams of `QXZV`, `WJKQ` and `HOLDING` are not in the vocabulary, so the query vector equals the one for `BEISPIELMARKT`. `nearest_distance == 0`, margin 1, accepted. The test I would expect: build from `[_row("BEISPIELMARKT", LEBENSMITTEL)]`, query `"BEISPIELMARKT QXZV WJKQ"`, and assert `"distance" in result.failed_gates`. I expect this to fail on the current patch. It is **unconfirmed**: scikit-learn is not installed in this sandbox, so I could not run it. The claim rests on documented `CountVectorizer`/`TfidfVectorizer.transform` behaviour (terms not in the vocabulary are ignored). In real partitions with a large vocabulary, some n-grams of the new words will be known, so the effect is partial, not total. But the direction is always the same: new text pulls the distance down compared with a vectoriser that counts it. The current novel-merchant test (`tests/test_knn.py:113`) only covers a memo that shares nothing with history (`NEUHEIM KIOSK`), which is the friendly case. The brief and proposal 0001 fix the exact vectoriser setup, so the fix is a design choice, not a builder slip. Options: measure what share of the query's n-grams are in the vocabulary as a coverage check, fit on partition + query, or use a hashing vectoriser. Each one changes what the distance threshold means, and #25's backtest calibrates against that. That is why this is tagged [human]. A downstream review still has to approve the row, so no booking reaches the book without approval.

- NEEDS-HUMAN [human] — **T2 threat-model currency** (`gate-logs/T2-threat-model.log`, `.oss-scanner/threat_model.md` "Components that matter most" item 5). The threat model names the kNN distance and margin gates but does not describe how distance is measured. If the finding above is accepted as a known limit instead of being fixed, the "Known gaps" section should say that the distance gate ignores n-grams not in the vocabulary, so later reviewers don't raise it again. Sign-off decides this; the builder can't.

## Checked, no finding

- **Gate bypass through float edge cases** (`classifier.py:213-224`, `:357-362`). A NaN distance clamps to 1.0 (`min(1.0, nan)` returns 1.0), and the comparisons are written `not x <= max` / `not m >= min`, so NaN fails both gates. `build` rejects NaN, infinite or out-of-range thresholds and half-lives (`:277-284`). If every weight underflows to 0, the total is 0, so the margin is 0 and the margin gate fails. The `_IDENTICAL = 1e-9` snap only matters when `max_distance` is below 1e-9, so it does not widen a threshold.
- **Empty or blank query, partition with no rows, partition of blank tokens**: all three return `failed_gates={"distance"}` with no candidate (`:202`, `:337-338`). Tested at `tests/test_knn.py:247`, `:275` and `:284`.
- **Provenance and synthetic rows** (Medium class): exact-type checks in `_check_row` (`:128-145`), run again in `build` (`:289-292`). Subclasses and objects with their own `__eq__` are refused, and the tests cover the hostile cases (`tests/test_knn.py:170-236`).
- **Single account, no split**: `KnnResult` holds one path. Failing a gate sets `account=None` (`:364`). No threshold is lowered.
- **Privacy**: `KnnError` messages name the field and type, never the token or account path (`:59-63`, tested at `tests/test_knn.py:438`). `_choice` echoes only the sign or provenance value. The diff adds no logging and no model call. Test data is invented (`BEISPIELMARKT`, `NEUBAU DROGERIE`, `build_corpus(0)`). No IBANs and nothing drawn from a real statement.
- **Pipeline/gnucash boundary and no-AI mode**: scikit-learn does not import `gnucash` and makes no network connection. The new dependency (`pyproject.toml`, `scikit-learn>=1.5`, no upper pin) was settled at Plan.
- **Resource use**: cost per query is linear in token length and partition size (brute-force search). Nothing grows out of proportion to a hostile memo.
- **Book writes, review file, idempotency, money, documents**: none of these surfaces is touched.
