# Security review: issue 24, kNN index with abstention gates

**Untrusted input this diff touches:** the query `token` passed to `KnnIndex.query`. It is the normalised memo of a statement line (threat model "Where untrusted input enters" #1: counterparty text). Index rows come from the user's own booking history (trusted), and thresholds and `exclude` come from the caller (internal). No book write, review file, model adapter, paperless path or money path is touched.

## Findings

- NEEDS-HUMAN [human] — **Low to Medium (abstention erosion; nearest rating: "a gate that lets a low-confidence proposal through as confident")**, `src/autobook/pipeline/classifier.py:269` (`_Partition._distances`, query weight `(1 + ln count) * idf`), with `sublinear_tf=True` at `:205`. **Input:** memo text. **Who controls it:** any counterparty, or a bank's memo format by accident. **What goes wrong:** unseen n-grams (character fragments) do push the query away from history, as criterion (k) asks. But repeating a *known* merchant name raises the weight of its n-grams by `1 + ln c`, and since those n-grams point in the same direction as the history row, the novel part of the memo gets diluted. A memo for a merchant the user has never booked can then pass the distance gate and get pre-marked `a`. Saving the review file approves it. **Reproducer** (index of one row `BEISPIELMARKT` → `LEBENSMITTEL`, `GIROKONTO`/`out`). I computed this with a pure-Python copy of the patch's formula; the same copy reproduces criterion (k)'s 0.2368 and 0.3589. The query `NEUERLADEN STROMANBIETER BEISPIELMARKT` scores distance 0.592 (it abstains at `max_distance=0.3`). With the name repeated 3 times it scores 0.316, 5 times 0.241 (accepted at 0.3), and 10 times 0.172. The margin gate does not help here, because the only neighbours all vote for one account. The brief chose sublinear tf on purpose (brief lines 93 and 115), so this is a design question, not a builder slip. Options: use binary query term frequency (each n-gram counts once), dedupe repeated words in the token before the query, or accept the risk and record it in the threat model. Whoever decides should also check whether #25's backtest would ever see memos like this; if not, a threshold fitted on clean history will not catch it. One unit test pins it: the query above with the name repeated 5 times must not be accepted at `max_distance=0.3`.

- NEEDS-HUMAN [human] — T2 gate is `unverifiable` (`gate-logs/T2-threat-model.log`): `classifier.py` changed without a threat-model update. The brief records this as a planned deferral to a follow-up issue, so it is settled under the reviewer protocol. Whoever signs off should make sure that follow-up's sentence on "how distance is measured" also covers the repetition behaviour above, if it is accepted rather than fixed.

## What I checked and found clean

- **Synthetic rows reaching the index (Medium in the threat model):** provenance is checked by exact type in both the `IndexRow` constructor and again in `build` (`classifier.py:122`, `:344`). `index_rows` copies provenance from the corpus row instead of setting it. Tests cover `object.__setattr__` bypasses, subclasses, and objects that define their own `__eq__` (e.g. `mock.ANY`). No finding.
- **A proposal passing with a gate failed (High):** the comparisons are written as `not nearest <= max` and `not margin >= min` (`classifier.py:431-433`), so a NaN fails both gates. Both gates are evaluated and reported. Empty partitions, all-blank tokens and an empty vote all abstain on `distance`. `min_margin > 0` means a tie is never accepted. Thresholds have no default and are range-checked, and bools are refused. No finding.
- **Crash or hang from a statement memo:** a non-blank token always yields at least one n-gram (padding gives length >= 3), so `squared > 0` and there is no divide-by-zero. Query cost grows linearly with memo length. Odd characters are handled the same way by `str.strip()` and the analyser's `split()`. No finding.
- **Personal data in errors or logs:** `KnnError` messages name the field and the type. `_choice` (`classifier.py:94`) echoes `value!r` only for `sign` and `provenance`, never for memo tokens or account paths. Nothing is logged. No finding.
- **Input order deciding the vote:** rows tied with the k-th distance all vote, and ties in the ranking are broken by path. Tests (j) cover oldest-first, newest-first and shuffled order. No finding.
- **Test fixtures:** all invented (`BEISPIELMARKT`, `MUSTERBAECKEREI`, `QXZV`); no IBANs; no new fixture files. No finding.
- **Pipeline/book boundary:** no `gnucash` import. The new runtime dependency is `scikit-learn>=1.5`; the threat model does not cover supply-chain risk, so I raise nothing on it.

Toolchain: scikit-learn is not installed on the host interpreter, so I did not run the reproducer against the real `TfidfVectorizer`. The pure-Python copy matches the brief's published values for (k), so I count the numbers above as confirmed.
