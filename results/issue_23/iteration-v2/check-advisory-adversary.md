## Findings

- NEEDS-HUMAN [impl] — `src/autobook/pipeline/normaliser.py:148-149`: if the user directory is a **broken symlink**, the loader silently treats it as missing. `os.scandir` raises `FileNotFoundError` for a link whose target is gone, and that error is mapped to "no user files". Reproduced: `~/.config/autobook/normaliser` → a dotfiles checkout that has moved or isn't mounted. `load(link).version` was `1-d7b5c9384833`, the same as `load(<absent dir>).version`. So the user's `accounts.toml` and overrides are dropped with no error, and the version doesn't change. This is the same silent drop that last round's fix closed for an unreadable directory. It also contradicts the patch's own rule that a broken *profile* link raises (`tests/test_normaliser.py:325-333`). Fix: when `FileNotFoundError` is raised, return `[]` only if `not os.path.lexists(directory)`; otherwise raise `NormaliserError`. Add a test with a dangling directory symlink.
- NEEDS-HUMAN [impl] — `src/autobook/pipeline/normaliser.py:126-127`: a relative `XDG_CONFIG_HOME` is used as given, so it resolves against the current working directory. The XDG Base Directory spec (the freedesktop.org rules for config paths) says relative values are invalid and must be ignored. Concrete case: with `XDG_CONFIG_HOME=rel`, `_default_user_dir()` returns `rel/autobook/normaliser` (checked). The profiles in effect, and so every token and the `version`, then depend on the directory autobook was started from. Fix: use the variable only when `os.path.isabs(config_home)`; otherwise fall back to `~/.config`. Add one `monkeypatch.setenv` test.
- NEEDS-HUMAN [human] — `src/autobook/pipeline/profiles/sepa.toml:36`: the end of a tag's value is found by looking ahead for the five named tags only. Other real SEPA field tags (`ABWE+`, `KREF+`, `IBAN+`, `BIC+`, `DEBT+`) are not boundaries, so they are swallowed into the previous value. Reproduced: `SVWZ+MIETE EREF+1 ABWE+MUSTER HAUSVERWALTUNG` → `MIETE`. The `EREF+` value runs to the end and takes the payee text with it. And `SVWZ+MIETE ABWE+X` would leave `ABWE+X` in the token. The brief names exactly five tags, so this follows the brief. A human should decide whether "up to the next SEPA tag" should cover the full tag set before #24 builds vectors on these tokens.
- NEEDS-HUMAN [human] — `src/autobook/pipeline/normaliser.py:242-251`: the version digest covers `NORMALISER_VERSION`, the profiles and the mapping. It does not cover the interpreter's Unicode database. `str.upper()` (`:87`) and the regex classes `\d`, `\b`, `\s` all depend on it, and CI supports Python 3.11–3.14 (`.github/workflows/ci.yml:69`), which ship different Unicode versions (this sandbox has 16.0.0). A memo with a character whose case mapping or digit property differs between those versions gives different tokens under the same `version` string. The real-world risk is small. Whether the interpreter or Unicode version belongs in the normaliser version, or in the ch.8 §8.3 tuple, is a scope call.

## Not raised as NEEDS-HUMAN (attempted, low value or follows the brief)

- `src/autobook/pipeline/profiles/sepa.toml:36` (no `\b` before tags, a deliberate trade-off from last round): a word that ends in a tag name eats the text after it. `SVWZ+SCRED+ SOFTWARE` → `S`. I found no realistic memo that triggers this; `ABWASSER+STROM` is safe.
- `src/autobook/pipeline/profiles/default.toml:26` (`\b\d+\b`): merchant names with digits get mangled, e.g. `1&1 TELECOM` → `& TELECOM` and `24/7 FITNESS` → `/ FITNESS`. The brief explicitly asks for "standalone digit runs" to be removed, and a user can override the profile.
- I also tried these and could not break them: duplicate or unknown mapping entries, non-string or extra keys, invalid regex, a user-directory path that is a file, version stability across two directories, rule order in the digest, `raw_memo` coming back unchanged, and the `test_skeleton.py` exemption (it skips only the three stub-shape assertions).
