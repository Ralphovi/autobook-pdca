# Adversarial review — issue 25 / rolling-origin-backtest

The red→green proof is real, but the fix has one crash, and the gating C4-ci row is red.

**Evidence re-run.** I ran `tests/test_backtest.py` and `tests/test_skeleton.py` against `$PDCA_TARGET` with a Python that has scikit-learn 1.9.1: 15 passed. The red leg in `gate-logs/C4-verify.log` fails for the right reason. All 10 backtest tests fail with `AttributeError: module 'autobook.pipeline.trial' has no attribute 'backtest'/'main'`, with no collection errors. The tests call the production `trial.backtest` and `trial.main`, not a copy of them. I also checked the sweep against real reruns: on a planted corpus with 4 novel rows, all 90 grid cells of `novel_sweep` matched a full `backtest()` rerun at each (max_distance, min_margin), and 60 of the cells were non-zero. So the sweep code is correct even though its test is weak (see below).

## Findings

- NEEDS-HUMAN [impl] — The gating C4-ci row fails on both attempts (`gate-logs/C4-ci.log`). `ruff check` raises PLR0402 at `tests/test_backtest.py:21`, `:22` and `:23` (`import autobook.pipeline.trial as trial` etc.). `ruff format --check` wants to reformat `tests/test_backtest.py:105-107`. The brief prescribed the `import a.b.c as c` form, but `from autobook.pipeline import trial, normaliser` / `from autobook import contracts` is also a module-scope module import, so it collects on the red leg too. Existing tests already use that form (`tests/test_knn.py:23`, `tests/test_normaliser.py:24`). Then run `ruff format`. Until this is fixed, the gate is red and the patch cannot be accepted, whatever the review says.

- NEEDS-HUMAN [impl] — `src/autobook/pipeline/trial.py:125-128` crashes with `ZeroDivisionError` when a month's past rows in a `(source_account, sign)` partition all have blank tokens and the test row has words. In that case `vocabulary == 0` and the class word count is 0, so `denominator == 0`. Blank tokens are normal normaliser output: under the `default` profile, `"12345"`, `"REF 99"` and `"  "` all normalise to `''`. Concrete failing case: January has one row `"12345"` → `MIETE`, February has one row `"ALPHA"` → `MIETE` (both `GIROKONTO`/`out`). `backtest()` raises `ZeroDivisionError` at `trial.py:128`. On the CLI path, `main()` (`trial.py:413-416`) catches only `ContractError`/`NormaliserError`/`KnnError`/`OSError`/`UnicodeDecodeError`, so a real corpus export with a reference-only first month in some partition ends with a traceback, not a report. Guard `denominator == 0`, or use `vocabulary + 1`-style smoothing so that unseen words still give a finite likelihood, and add a test.

- NEEDS-HUMAN [impl] — The threshold-evidence path is barely tested. `tests/test_backtest.py:221-228` only checks a sweep where every cell is `accepted == 0` (one novel row at distance 1), so any sweep that returns zeros passes. I mutated `trial.py:212` from `o.candidate_correct` to `o.correct` (only rows accepted at the run's own thresholds). That would make sweep precision wrong at every looser grid point, which is exactly the number a human sets thresholds from, and all 10 tests still passed. These mutants also survived: the token-Bayes prior dropped (`trial.py:126` → `score = 0.0`), Laplace smoothing removed (`trial.py:128`), the leave-one-out `seen` rule changed to `> 0` (`trial.py:359`), and the `seen` key made to ignore the `(source_account, sign)` partition (`trial.py:300/304`; no test has two partitions). The code is correct today, but nothing pins it. Add one planted near-match novel row (for example `ALPHA MARKT` history vs `ALPHA MARKET`) with expected sweep `accepted`/`correct` at two grid cells, plus a two-partition `seen` case.

- `src/autobook/pipeline/trial.py:300,304`: a row whose token is blank (`''`) counts as `seen` when any earlier row in the partition was also blank. kNN can never classify it (`classifier.py:226` returns no voters), so it is always a `seen` abstention, while token-Bayes accepts it on priors alone. With my probe (Jan `"12345"`, `"ALPHA"`; Feb `"6789"`), the kNN `seen` stratum showed rows 1, accepted 0, coverage 0.0. On a real book with many reference-only memos, this drags down `seen` coverage and makes `seen` look worse than it is. It follows the brief's literal definition ("same token"), so this is a note for the human reading the report, not a defect.

- `src/autobook/pipeline/trial.py:413-414`: for a bad row, the CLI writes `str(ContractError)` to stderr, and that string echoes the bad field's value. I got `corpus.rows[3].amount_cents: must be at least 1, got -4711` and `corpus.rows[3].post_date: not a calendar date: '2025-13-07'`. The brief asked for a one-line message, and only the malformed field is echoed (never the memo or account path: those messages report types, not values), so this is low risk. Still, "logs carry IDs, counts and versions" (ch.8 §8.5) is stricter than an amount on stderr. Separately, an `OSError` from `load_normaliser` is reported as "cannot read the corpus" (`trial.py:415-416`), which is a misleading message but harmless.

- `src/autobook/pipeline/trial.py:287-295`: months with no rows are skipped. They do not appear in `by_month` and are not counted in `tested`. The brief says "the calendar months from the first to the last `post_date`". An empty month adds no rows, so no metric changes, but `tested` undercounts calendar months. This is a cosmetic difference from the brief and does not affect the step-2 decision.

## Things I tried to refute and could not

- **Future leakage.** I mutated the history to (i) a global index and (ii) a bound of "before this row's date". Mutant (i) fails 5 tests and mutant (ii) fails 2, so criteria (b) and (e) catch both. `trial.py:297` bounds history by the first of the month, and `as_of` only affects decay.
- **Leave-one-out kept out of `methods` and the sweep.** `trial.py:334-341` and `:341` take only `knn_all`. Confirmed.
- **Report privacy.** The report holds only counts, rates, thresholds, band labels and `YYYY-MM` keys. `_Outcome` carries no token or account. The test at `tests/test_backtest.py:163-178` checks the merchant tokens and all account path parts.
- **NaN or inf thresholds from the CLI.** `KnnIndex.build` refuses them (`classifier.py:330-334`), and `trial.py:284` runs that check before any work. Exit code 2, no report.
- **Band edge at 1.0.** `bisect_right` puts a confidence of 1.0 in `[0.9,1]`. Confirmed.
