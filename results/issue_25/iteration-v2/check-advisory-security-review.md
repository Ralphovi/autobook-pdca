# Security review: rolling-origin backtest (issue 25)

**Attacker-reachable inputs this diff touches:** the memo text inside a `corpus` contract file (threat model "Where untrusted input enters" #1: counterparty text, carried into the corpus export), read by the new CLI `--corpus` path. Everything else the CLI reads is trusted under the threat model: the destination accounts (the user's own booking history), the `--normaliser-dir` profiles (the user's own config), and the threshold flags (the user's own command line). The diff has no book write, review file, model adapter, paperless, staging or money path.

**Verdict: no finding.** The one property in reach is "Nothing personal leaves the machine" (no memo, account name or amount in a log or shareable artifact). The report and the error output both keep it.

What I checked:

- **Report contents.** `src/autobook/pipeline/trial.py:417-445` (patch lines). Every report key is a constant or a `YYYY-MM` month label (`_label`, `_band_labels`, `_STRATA`). Values are counts, rates, thresholds, `HALF_LIFE_DAYS` and `normaliser.version`. No dict key or value is built from a token, memo, account path or amount. `_Outcome` (`trial.py:179-190`) holds only booleans and floats. A crafted memo therefore cannot add or change a report field. The normaliser version is a digest (`target/src/autobook/pipeline/normaliser.py:351-375`), so the account paths it hashes are not exposed.
- **stderr on refusal.** `main()` writes `str(exc)` for `ContractError` / `NormaliserError` / `KnnError` (`trial.py:517-518`). On the target, `ContractError` messages name the field location and type (`target/src/autobook/contracts.py:199-247`) and never echo `raw_memo` (`_text` echoes only the type). The only echoed values are a non-ISO date string (`contracts.py:282-290`) and an `amount_cents` below 1 (`contracts.py:133`, `:235-240`), on the user's own terminal. That is Low at most, it comes from existing contract code, and this diff does not change it. `NormaliserError` input checks deliberately leave out memo and account names (`normaliser.py:378-391`). `OSError` / `UnicodeDecodeError` output only the exception type name (`trial.py:519-520`), not the path or the bytes.
- **Threshold input.** A NaN or infinite `--max-distance` / `--min-margin` is refused by `KnnIndex.build` (`target/src/autobook/pipeline/classifier.py:328-334`; `not 0 <= nan < 1` is true). `backtest()` calls it before anything else (`trial.py:387`), so `json.dumps(..., allow_nan=False)` cannot crash on a NaN threshold. A threshold can't be lowered "for one case": the report is evidence only, and nothing in the diff writes a threshold.
- **Crash or hang from the corpus file.** The divide-by-zero from the previous round is fixed: `trial.py:225` keeps only words in the partition's vocabulary, so `vocabulary >= 1` wherever the denominator is used. `test_a_history_of_blank_tokens_still_gives_a_report` covers the reproducer from round 1. Cost grows as months × history size, in line with the input. This is a trial tool run by the user on their own export, not a pipeline stage.
- **Report file.** The report is written only after the backtest succeeds (`trial.py:521-525`), so a refused input leaves no file. The test checks this for a wrong contract, invalid JSON and a missing file (`tests/test_backtest.py`, `test_cli_refuses_a_file_that_is_not_a_corpus`). It is created with the default umask, not `0600`. Since it holds counts only, that is not a finding. It is not a downloaded original or a review file, so the `$XDG_RUNTIME_DIR` rule does not apply.
- **Privacy test.** `test_cli_writes_a_report_without_identifying_data` checks the serialised report for every fixture merchant token, the novel merchant, every account path component and an ISO day. That covers the hostile case for this surface: the corpus is the only untrusted input, and its text is what the test searches for. The fixtures are synthetic (`tests/fixtures/synthetic/corpus_builder.py` plus invented `ALPHA`/`BRAVO`/`ZULU KIOSK` rows).
- **Other surfaces.** No `gnucash` import (the module docstring and imports at `trial.py:125-149` use contracts, classifier and normaliser only). No network, no model adapter, no float on a monetary path (amounts are never read by the backtest).

Gate evidence: `check-gates.json` shows C4-ci and C4-verify both pass (C4-verify: 14 of 19 tests red without the fix, all green with it).
